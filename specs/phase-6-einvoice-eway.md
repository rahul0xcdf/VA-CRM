## 1. Deliverables (project.md §10)

NIC sandbox API client (auth, IRN generation/cancellation, signed QR), e-way bill API client
(Part-A/B, generate by IRN, cancel/extend).

## 2. Scope notes

- **E-invoicing (NIC IRP):**
  - Auth: RSA encryption of the app key, AES-256 session key (SEK), token lifetime handling and refresh.
  - **IRN** = SHA-256 hash of Seller GSTIN + Document Number + Document Type + Financial Year.
  - Signed **QR code with its 10 mandatory fields**, printed on the invoice.
  - Cancel within the 24-hour window; after that, a credit note is the only route.
  - **Sandbox first** (`einv-apisandbox.nic.in`). Production endpoints are switched on only after
    sandbox sign-off by the project owner.
- **E-way bill:**
  - Part-A / Part-B workflow; generate directly from an invoice **or** by IRN.
  - ₹50,000 threshold; validity of 1 day per 200 km.
  - Cancel within 24 hours; update vehicle/transporter; extend validity.
- **Resilience is part of the deliverable, not a nicety:** every IRP call is idempotent from our side,
  request/response pairs are persisted, failures are retryable without producing a duplicate IRN, and
  a network outage never leaves an invoice in an ambiguous state. Credentials are stored encrypted at
  rest (DPAPI in the single-user phases) and never written to logs or committed.
